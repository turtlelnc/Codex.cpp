# Creator 工程与安全复审（PR #12）

本轮审查以 `465035d` 为起点，先核对该提交 7 项 CI 全绿，再检查代码及负面场景。此文记录验证范围，不是第三方安全认证。

## 已确认并修复

- **审阅/启用脱节**：旧报告虽有文件 SHA，但生成的 `--penguin` 启动参数未绑定它们。新增 `--penguin-reviewed MANIFEST SHA256`；启动比较文件指纹映射，使用读取到的同一批字节建立私有快照，然后加载/服务资源。没有“比较后又打开原文件”的加载窗口。叶文件和目录路径分别通过句柄检查，不跟随链接。
- **WebUI 子进程降级**：直接把 reviewed 参数扩展到父服务后，浏览器替换原文件测试发现 Agent worker 仍传原始 `--penguin`。现在 worker 继承父快照和原指纹，再次验证；父/子快照从模型文件工具和 OS 子进程隐藏，包括快照位于获授权的大工作区之内的情形。
- **旧产物假成功**：`--clean-first` 能处理旧时间戳，但成功的空 CMake 工程仍可保留清单指向的旧库。现在先验证产物在 build/ 内、沙箱可用，再安全删除旧库，成功返回前要求重新产出。负面测试不会把库清理指向源码。
- **EOF/退出混淆**：旧 runner 看到管道 EOF 后只等 1 秒，进程合法继续执行也会超时。现在 EOF 与进程退出分别处理，完整执行预算、取消和 tick 持续有效；读取错误单独失败。
- **进程启动清理竞态**：POSIX stop 只向进程组发送信号，在刚 fork 尚未 setsid 的窗口可能漏掉直接子进程。现在同时终止直接 PID；普通进程树、忽略 TERM 子进程及异常退栈均测试延迟写不会发生。
- **探测派生进程**：macOS ABI 探测无需 fork，现已明确禁止，避免初始化器通过脱离进程组留下后台任务。Linux 使用 bubblewrap PID 命名空间。没有关闭沙箱或扩大写入/网络权限。
- **审批语义与旧状态**：构建执行任意 CMake，现走命令审批，且独立拒绝只读策略；拒绝策略级 unsafe override。新构建（含失败）使旧审阅卡和探测结果失效。报告区分结构、构建、ABI、功能、安全审阅和启用授权。

## 测试证据

- `tests/penguin_creator_test.cjs`：替换清单/原生库/源码/JS、错误指纹、真实危险初始化器的旧 pin 拒绝、硬链接、叶符号链接、目录符号链接/Windows junction；CLI/模板/无覆盖；空构建不得沿用库；禁止工作区写/父凭据读取/父秘密环境继承；10 秒超时。
- 旧 mtime 测试先用普通增量构建复现库 SHA 不变，再用 Creator 构建确认 SHA 改变，随后验证挂起初始化器的 10 秒期限。没有延长期限来掩盖旧 macOS CI 失败。本机能够证实这个失效机制；不能从历史日志断言每次 macOS 故障只有这一种原因。
- `tests/creator_process_checks.inc`：真实 `ManagedProcess`/Creator runner，提前 EOF 后的实际退出码、超时、取消、回调异常、子进程延迟写、目录清理、unsafe 拒绝、审批/只读，以及获授权工作区内的继承快照保护。三平台 CI 都执行该专用入口；Windows 验证 fail-closed。
- `tests/penguin_creator_browser_test.cjs`：真实 Chromium/C++ 服务 + 确定性本地模型；审批拒绝/同意、生成/编辑/构建/探测/审阅、命令复制、移动布局、未自动启用；显式 reviewed 启动后替换原库/JS，网页交互及新 Agent worker 的实际原生工具仍正常。
- `tests/webui_quality_test.cjs`：旧探测失败/重新构建不能显示旧成功；保留布局/保存竞态/流式渲染/审批等现有回归。核心 self-test、HTTP smoke、流式和单文件测试继续执行。

最终跨平台结果及对应提交见 PR #12 的 CI 链接与提交记录；本地测试不能代替 Windows/macOS 实机 CI。

## 保留的设计取舍与风险

1. 正式运行的原生代码仍是宿主完整权限的受信代码，能访问文件、凭据、网络及宿主内存；声明/工具审批不能约束恶意原生代码。Creator 不提供无权限插件运行时。
2. pin 只绑定列出的字节，不是签名、授权或恶意代码检测，也不证明源码/二进制对应关系。系统运行库、第三方动态依赖、插件主动读取的外部资源不在最小快照证明内。复杂依赖需要单独人工审阅/部署；不自动复制未知文件。
3. 旧 `--penguin` 故意保留直接信任当前目录的兼容语义，包含后续 worker 再次加载它；不具备 reviewed 模式保证。不要在旧模式加载 Agent 可写目录。新 Creator 不生成这种命令。
4. macOS 构建必须允许编译器 fork。当前进程组清理覆盖普通编译树，不能保证终止故意 setsid/双重 fork 的对抗性构建后台进程；Seatbelt 权限仍有效。需要强对抗构建时用独立账号/容器/VM。本轮到此停止扩大进程监管架构。
5. Windows 没有 AppContainer：自动构建/探测拒绝，而非降级；静态审阅/手工编译/显式加载仍支持。Linux 全静态 musl 的 dlopen 限制保持不变。
6. 快照位于当前用户私有执行目录，不防御同账号的沙箱外恶意进程或已经正式加载的恶意原生模块。异常终止可能遗留临时目录。功能/安全审阅与正式授权始终由用户和外部测试决定。
