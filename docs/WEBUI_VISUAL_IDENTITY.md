# WebUI 视觉身份：Workbench（2026-11-11）

交互结构保持 [Code 模式界面参照](WEBUI_CODE_DESIGN.md) 的三栏布局、工具双层披露、审批独立展示、焦点恢复与减少动效处理；本次只替换视觉系统、空状态文案与品牌标记。目标是让 WebUI 读起来像本地代码工作台，而不是暖米色 + 砖红的聊天产品复刻。

## 设计原则

1. 机器输出用等宽，人的文字用无衬线：字体家族编码内容来源。
2. 规则先于盒子：分组用 1px 分割线与留白，不用卡片阴影。
3. 只有一个信号色，且只给“正在发生 / 可以行动”的状态。
4. 文案是操作语言，不是口号；首屏不使用随机欢迎语。
5. 预览结果必须带着它自己的能力边界，不伪装成浏览器。

对比度（亮色）：墨色/纸面 16.0:1，次级/纸面 5.4:1，信号/纸白 6.4:1；暗色同样不低于 4.5:1。

## 字体与形状

- 正文：系统无衬线，15px / 1.72，阅读宽度 760px。
- 机器声音：导航标签、页签、状态、命令、工具名、元数据、空状态操作使用等宽字体，10.5–11.5px；不使用全大写。
- 形状：控件 4px、composer 与浮层 8px、面板 0；唯一的浮层高度来自 `--shadow`。
- 用户消息用左侧 2px 墨色竖线标记，不使用气泡；文本与助手正文保持同一列对齐。

## 首屏与品牌

- 移除 ⌘ 标记；字标前的方块是选中态/终端窗口的抽象，不使用字体字符。
- 首屏固定为「本地代码工作区」，下面给三条可执行任务，不再使用服务端随机中英文欢迎语。点击任务只填入输入框并聚焦，不自动提交；是否发送仍由 Enter 或发送按钮决定。
- 预览图片下方显示 MiniWeb 能力边界条：由预览工具的能力报告生成，列出被忽略或近似的特性；干净页面显示“未检测到已知不支持项”，但明确说明缺失不代表完整支持。

## 验证

- `tests/webui_quality_test.cjs`：真实 Chromium 的布局断点、滚动/选择、焦点、移动侧栏、减少动效与消息缓存回归。
- `tests/miniweb_test.cjs`：真实 C++ 服务、假模型、`preview_screenshot` 链路；检查预览能力条进入 WebUI。
- 手工截图检查 1440×900、390×844、亮/暗色与检查器展开；对比度按 WCAG AA 文本阈值计算。

## 边界

- 仅改变视觉与首屏文案，不改 RPC、权限、持久化或 Agent 行为。
- 系统字体在不同平台仍有字形差异；未引入 Web 字体或前端构建依赖。
- 未在 Safari、Firefox、实体触屏或屏幕阅读器中验证。
